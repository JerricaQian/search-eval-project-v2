# 页面框架评测

本目录的 7 项 Skill 以搜索词×页面（Tab）为结论单位，组件、区域、列表位和卡片比较都只作为页面证据；不把组件内部问题重复写成页面问题。每项均按“评审对象与共同契约 → Phase2 事实/测量门槛 → 专属判定标准 → 评级与问题项 → 固定流程 → 输出模板 → Gotchas”执行。

## Skill 清单

| Skill | 只评什么 | 评级与 Tab 分数 |
|---|---|---|
| `eval-1` 供给呈现质量（页面框架完整性） | 核心/辅助页面模块是否存在并正常加载 | 优秀 `0` / 达标 `-1` / 不达标 `-2`，每页一结论 |
| `eval-2` 视觉秩序统一对齐 | 结果列表卡与筛选栏以上主点卡、运营卡、异构横插卡的统一样式去重数；排除“大家还在搜”和提示浮层 | 优秀 `1` / 达标 `0` / 不达标 `-1`，每页一结论 |
| `eval-3` 色彩运用有逻辑 | 全部结果卡七色集合的页面级并集数量 | 优秀 `1` / 达标 `0` / 不达标 `-1`，每页一结论 |
| `eval-4` 静态组件不复杂 | 首屏独立功能区数量 | 优秀 `1` / 达标 `0` / 不达标 `-1`，每页一结论 |
| `eval-5` 浏览动线顺畅 | 前 10 个有效列表位中的异构形态数 | 优秀 `1` / 达标 `0` / 不达标 `-1`，每页一结论 |
| `eval-6` 信息可比性 | 同业务语义、同卡型卡片的同字段表达 | 优秀 `1` / 不达标 `-1`，每页一结论 |
| `eval-7` 功能/信息无冗余 | 不同页面区域间是否有无增量的重复功能/信息 | 优秀 `1` / 不达标 `-1`，每页一结论 |

## 阅读顺序

1. 依据任务选择上表中对应的一个或多个 Skill；页面结论只由目标 Skill 的页面证据得出。
2. 先读 `contract.md` 与当前截图的 Phase2 页面、卡片和原子事实。
3. 再完整读取目标 `skills/eval-*/SKILL.md`，按其专属门槛、测量/扫描、阈值、评级和 Gotchas 执行。页面视觉秩序只读取 Phase2 JSON，从 `cards` 与 `pageFacts.modules` 建立统一供给卡样式库存并执行排除/去重；页面色彩只读取 Phase2 JSON 已确认的颜色角色并对组件色系取并集，不运行取色脚本；信息可比性与跨区冗余直接全量遍历 Phase2 JSON，不运行候选脚本。
